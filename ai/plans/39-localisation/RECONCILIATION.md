## Owner rulings taken in this session

- **D34 (2026-10-10): the language switch is forward-only convergence.** Store the selected language and a last-armed stamp; the UI switches immediately; surfaces (re-arm, channels, widgets) reconcile whenever the two differ, at launch and on foreground. This displaces D18's rollback layer and retires D28's failure face: a switch can no longer fail user-visibly, it converges. The reworded guarantee, which all four branches agree is the strongest any design can deliver: never fewer alarms (identifiers never change), the UI is never half-applied, and surfaces converge by the next process start. Adopted from the consensus of verify A1, the claude alternative's design 3, and the opencode-deepseek requested/applied pair; D18's literal "no half-applied state" was proven unachievable for 64 separate native calls (TXN-10). R11's rollback machinery, TXN-8/9/11 (false success, no marker repair path, marker direction ambiguity) all dissolve. Stage one builds none of this; row 39 inherits the design.
- **D35 (2026-10-10): no keep-list additions, ever; a clean database outranks legacy comfort.** A13 (keeping `scheduled_*` records through the pre-marker wipe) is rejected in the owner's words: preserving old data the new version does not need saves junk, and saving junk now means saving junk forever. The wipe stays exactly as it is. The pre-marker population's offline bell-off gap closes when their cache refetches, and shrinks to zero when the current 1.29.x reaches the stores.

## Architecture repairs (ADOPTED into steps 06, 07, 14)

- **ARCH-13 / A6: stronger `t()` types.** Every catalog carries `satisfies Catalog`; parameters are typed per key via the English literal's placeholder inference; no English fallback exists at runtime (D17/D24 make a silent fallback a wrong answer). Four type lines, measured at 0.016 s for fifty 164-key catalogs.
- **ARCH-14 / A3: the bridge format is flat key-value JSON with `{name}` placeholders, not i18next JSON.** The catalog is already its own transfer format; i18next's `{{x}}`, reserved suffixes and nesting buy nothing and constrain keys. Step 07 exports and imports the flat shape with a CI round-trip parity test. This also dissolves C16 (tooling choice): extraction, when a TMS ever demands it, runs against the flat format; no tool is adopted now.
- **ARCH-17: the format-deciding pre-flight cannot sit after the format is built on.** Step 06 lands the catalog behind a one-module loader (`currentCatalog()`); the 3T require-timing experiment in step 15 decides TS-require versus embedded-JSON `JSON.parse` by rewriting that one module's body, never the call sites.
- **ARCH-5 / CNT-4/5/6 / A4: one AST scanner is both the census and the step 14 guard.** `scripts/scan-strings.mjs` (in this folder's `scripts/`, `@babel/parser` already installed) parses JSX text, string literals and template literals with expression context, classifies display copy, and emits the census JSON the waves consume. The guard is two parts: a context-scoped AST scan refusing new display literals in the scanned trees with a zero-length exclusion list, plus the rule that the named data modules (`shared/help.ts`, `shared/whatsNew.ts`) export catalog keys only. The plan stops quoting 123/25 as work counts; the scanner's output at the planned-at sha is the count of record.
- **ARCH-3 / A2: month and weekday names become catalog entries (31 keys per locale), not an `Intl` or date-fns tag swap.** Verified: the Gregorian label is date-fns (`shared/time.ts:232`), which has no Somali locale; an `Intl` swap changes order and era affixes and hands Thai a Buddhist-era year; two widget parsers assume the English shape.
