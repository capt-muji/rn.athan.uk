# Baseline 1.3 — Spam suites + blocked time (both devices)

## Android (raw adb input spam — true crazy-child rate, ~8–12 taps/s)

| Suite | Stimulus | ANR | Input timeout | Janky | p50/p90/p95 |
| --- | --- | --- | --- | --- | --- |
| Alert icon → instant backdrop ×10 | bell tap + 100ms backdrop tap | 0 | 0 | 69.9%* | 21/30/34ms |
| Sheet open/close collisions ×8 cycles | gear tap + gear tap + back | 0 | 0 | 64.0% | 19/28/36ms |
| Rapid page switching ×20 swipes | 100ms flings back-to-back | 0 | 0 | 23.9% | 11/23/30ms |
| Toggle spam ×20 @80ms | "Show hijri date" flips | 0 | 0 | 64.6% | 19/32/36ms |
| Sound select spam ×20 @100ms | rows in sound sheet (approx band) | 0 | 0 | **89.3%** | 25/38/42ms |

*cumulative window (not reset between alert runs); others reset per suite.

**Verdict: no ANRs, no lost input, no freezes — Android "blocking" manifests as jank.**

## iOS (WDA taps; injection ceiling ≈ 2 taps/s — WDA tap POST RTT ≈ 550ms)

Blocked-time proxy = `/source` AX-snapshot fetch duration (idle ≈ 1000ms):

| Suite | source fetch during/after (ms) |
| --- | --- |
| alert+backdrop ×10 pairs | 926–1247 (≈ idle — no blocking) |
| sheet open/close spam ×8 cycles | 898–1002 (≈ idle) |
| rapid page switching ×15 pairs | 931–1008 (≈ idle) |
| toggle spam ×20 @~2/s | **2002–2143 (2× idle — main thread saturated)** |
| sound select spam ×20 @~2/s | **1739–2145 (2× idle — main thread saturated)** |
| after close (settled) | 1034 (back to idle) |

**Verdict: iOS never hard-blocks either; toggle/sound spam doubles AX latency (main
thread busy). True high-rate spam not injectable via WDA — device truth comes from
xctrace (1.4).**

## Key harness facts (learned, reuse)

- WDA tap POST RTT ≈ 550ms; /source RTT ≈ 1.0s idle, ~2.0s under load. Absolute
  latencies carry this bias; deltas valid.
- adb `input tap` RTT ≈ 30–80ms → real spam only on Android.
- Sound-sheet rapid selects are the single worst render path on BOTH platforms.
