System floor ≈ 0.6–0.8s (A12/iOS 18 tax, mostly not ours). The app-attributable gap
(first frame → data-driven content ≈1.1–1.6s) is backlog #1's real target.

### Toggle spam Time Profile (25s attach, 18 flips)

Top burn (6713 frame samples):
1. `hermes::vm::Interpreter::interpretFunction` — dominant (JS execution: jotai writes,
   reschedule cascade, widget settings sync per flip)
2. `facebook::react::sliceChildShadowNodeViewPairsRecursively` — large shadow-tree
   clone/diff per toggle (whole-tree re-render incl. always-mounted overlay subtree)
3. `facebook::yoga::calculateLayoutImpl` — layout passes per re-render
4. `objc_msgSend`/`UIViewAccessibility` — native view + AX churn

## Android (3T)

### Idle CPU — THE headline finding

- `dumpsys cpuinfo` (windowed): **49%** (44% user + 5.7% kernel, 2902 minor faults)
- `top -n 1` (instantaneous): **90.3%**
- Sustained 40s+ after launch settle, app foregrounded, no interaction.
- Half a core burned at idle = thermal + jank headroom loss + battery. Points at
  backlog #4 (tick consolidation: 3 store + 3 hook + 2 interval timers) and #7
  (pino call-site gating, TICK ×5/s).

### Cold start framestats

ThisTime 3547ms (consistent with 1.1 median 3668ms); only 19 frame rows captured —
most of cold start is NOT frame rendering (it's process+JS+mount before frames flow),
matching the iOS picture (long pre-first-content stall).
