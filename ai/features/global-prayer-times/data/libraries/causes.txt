## Cause 1: Dhuhr method offsets, not astronomy

`adhan` CalculationMethod.ts L8 sets `methodAdjustments.dhuhr = 1` for MWL.
`praytime` praytime.js L49 defaults `dhuhr: "0 min"`. Removing adhan's +1
collapses the Dhuhr disagreement.

## Cause 2: Maghrib preset drift between the two PrayTimes lineages

`praytime@3.2.0` praytime.js L45 defaults `maghrib: "1 min"`, and its MWL
entry at L35 does not override it, so MWL Maghrib is sunset + 1 minute.
`praytimes@0.0.5` praytimes.js L62 sets `maghrib: "0 min"` for MWL. `adhan`
PrayerTimes.ts L183-191 uses sunset with no offset. This is the whole
difference between the two PrayTimes columns in the Maghrib table.

## Cause 3: Asr declination epoch, noon versus at-time

`adhan` SolarTime.ts L93-99 computes the Asr shadow angle from the NOON
declination and solves the hour angle once. The comment on that function is
`// TODO source shadow angle calculation`. `praytime` praytime.js L279-284
evaluates the declination at the Asr time itself, and L169-170 re-runs the
whole pass `iterations` times. Raising `iterations` moves praytime further
from adhan, which is the proof that this is the mechanism and not rounding.

## Cause 4: what "the night" means in the high-latitude rule

`adhan` PrayerTimes.ts L109 defines the night as `tomorrowSunrise - sunset`,
so it spans the real night. `praytime` praytime.js L296 uses
`24 + times.sunrise - times.sunset`, both from the SAME day, which is a
different interval whenever the day length changes. Below is the Fajr delta
with each of the three rules, which shows the rule choice dominating.

## Cause 6: rounding rule, with the astronomy held constant

`adhan` DateUtils.ts L22-35 `roundedMinute`: `Nearest` rounds up at >= 30 s,
`Up` always adds `60 - s` (so it moves a time even when s is 0), `None`
leaves the seconds. `praytime` praytime.js L230-240 maps `up`/`down`/
`nearest` to `Math.ceil`/`Math.floor`/`Math.round` on whole minutes, and any
other value returns the raw timestamp. Same instants, four rules:
